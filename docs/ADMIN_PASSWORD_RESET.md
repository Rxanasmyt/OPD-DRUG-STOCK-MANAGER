# ให้ Admin รีเซ็ตรหัสผ่านผู้ใช้ (กรณีลืมรหัส)

Firebase เปลี่ยนรหัสผ่านของ "คนอื่น" ได้เฉพาะจากฝั่งเซิร์ฟเวอร์ (Admin SDK) โปรเจกต์นี้ไม่ใช้ Cloud Functions/แผน Blaze
จึงทำเป็น **GitHub Action ที่สั่งรันเอง** (`.github/workflows/reset-user-password.yml` → `scripts/reset-user-password.mjs`)
ใช้ secret `FIREBASE_SERVICE_ACCOUNT_KEY` ตัวเดียวกับสคริปต์อื่นของ repo

> **repo นี้เป็น public** — log และ Job summary ของ Actions ใครก็เปิดอ่านได้ จึง **ไม่พิมพ์รหัสผ่านที่ใดบน GitHub เลย**
> รหัสชั่วคราวถูกเก็บใน Firestore (`passwordResets/{uid}`) ซึ่งอ่าน/ลบได้เฉพาะ Admin ที่ล็อกอินในแอพ (ตาม `firestore.rules`)

## วิธีใช้
1. แอพ → หน้า Admin → ผู้ใช้ที่ลืมรหัส → **🔑 รีเซ็ตรหัสผ่าน (ลืมรหัส)** → **เปิดหน้ารีเซ็ต (GitHub)**
   (หรือ GitHub → Actions → "Reset User Password") — ต้องล็อกอิน GitHub ที่มีสิทธิ์เขียนใน repo
2. กด **Run workflow** → กรอก **username** (ปุ่ม "คัดลอก username" ช่วยได้) → Run
3. รอ ~1 นาที แล้วกลับมาที่แอพ กด **ดูรหัสชั่วคราว** → แจ้งรหัสให้ผู้ใช้โดยตรง
4. ผู้ใช้เข้าสู่ระบบด้วยรหัสชั่วคราว → แอพบังคับให้ **ตั้งรหัสผ่านใหม่ของตัวเอง** ก่อนใช้งาน
5. แจ้งผู้ใช้แล้วกด **ลบรหัสนี้ออก**

## สิ่งที่สคริปต์ทำ
- หา username ใน `users/` (ไม่พบ = ไม่เปลี่ยนอะไร); **ปฏิเสธบัญชี Admin ของแอพ** เว้นแต่ติ๊ก `allow_admin` ตอน Run
- สุ่มรหัส 12 ตัว (ไม่มี 0/O/1/l/I) → **เก็บลง `passwordResets/` ก่อน** แล้วจึงเปลี่ยนรหัส (กันกรณีเปลี่ยนแล้วไม่มีใครอ่านรหัสได้)
- ยกเลิก session เดิม, ตั้ง `users/{uid}.mustChangePassword = true`, บันทึก audit `user_password_reset` (ใครสั่ง/ให้ใคร ไม่มีรหัสผ่าน)

## ข้อควรรู้ด้านความปลอดภัย
- การสั่งรันต้องมีสิทธิ์เขียนใน repo (เจ้าของ/ผู้ร่วมงาน) ซึ่งมีอำนาจสูงอยู่แล้ว (แก้ workflow เองก็เข้าถึง secret ได้) — ไม่ใช่ Admin ของแอพทุกคนที่ทำได้
- ชื่อ username ที่กรอกจะเห็นในหน้าการรันสาธารณะ (ไม่ใช่ความลับมาก แต่ควรรู้)
- รหัสชั่วคราวค้างใน Firestore จนกว่า Admin กดลบ — ลบทุกครั้งหลังแจ้งผู้ใช้
- ยังไม่ได้ทดสอบกับ Firebase จริง (ทดสอบด้วย mock) — ลองกับบัญชีทดสอบก่อน
